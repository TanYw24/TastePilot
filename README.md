# TastePilot

TastePilot 是一个面向“今天吃什么”的智能菜谱推荐 Web 原型。

它的核心思路不是让用户做很多复杂筛选，而是让用户直接说一句自然语言需求，例如：

- `想吃点暖胃的`
- `今天想来个甜品，不要太腻`
- `想喝点提神的饮品`
- `一个人吃，15 分钟内搞定，最好省钱`

系统会先解析用户输入，再结合用户长期偏好、本地菜谱数据库和菜品标签，给出更贴近当下状态的推荐结果。

## 项目亮点

- 面向“选择困难”用户，尽量减少筛选负担
- 支持账号注册登录，保存个人偏好
- 支持自然语言输入，而不是只能点标签
- 支持时间段灵感标签，如早餐、午餐、下午茶、深夜加餐
- 支持心情相关标签，如安慰系、解压系、暖胃系、提神系、犒赏系
- 推荐结果会根据菜品标签做匹配，并保留一定随机性，减少重复感
- 支持收藏、跳过、浏览记录，用于后续个性化排序
- 整体界面采用暖色系、图片背景和玻璃质感风格

## 当前功能

### 1. 用户系统

- 本地注册 / 登录
- SQLite 保存账号信息
- 密码使用哈希保存

### 2. 偏好记忆

- 保存长期口味偏好
- 保存预算、时间、饮食目标、素食偏好
- 保存不喜欢的食材

### 3. 智能输入解析

用户可以直接输入一句话，系统会尝试识别：

- 口味方向：香辣、清淡、鲜香、重口、奶香、果香、咸香等
- 目标方向：减脂、高蛋白、下饭、聚餐、夜宵
- 场景方向：一个人吃、双人晚餐、家庭晚餐、下午茶、深夜加餐
- 类型方向：正餐、轻食、甜品、饮品
- 心情方向：安慰、解压、暖胃、提神、犒赏
- 限制条件：省钱、15 分钟内、不要太腻、不要正餐、不要咸口等

同时，项目已经处理了一部分“否定语义”问题。
例如：

- `想吃甜品不要正餐`
- `想吃甜品不要咸的`

这类输入不会再被误判回正餐方向。

### 4. 标签辅助输入

- 输入框左侧可以展开常用标签
- 标签会根据本地时间段变化
- 已选标签支持删除
- 标签只是辅助，不是唯一输入方式

### 5. 菜谱推荐

- 根据解析后的标签与菜谱数据库做匹配
- 推荐时区分正餐、轻食、甜品、饮品，避免类型混淆
- 支持 follow-up 收窄操作，例如：
  - 更清爽一点
  - 更快一点
  - 更省钱一点
  - 更适合下午茶

### 6. 用户行为记录

- 收藏菜谱
- 跳过菜谱
- 浏览记录

这些行为已经写入本地数据库，可继续用于更细的个性化推荐。

## 数据设计

菜谱数据的主要字段包括：

- `id`
- `name`
- `cuisine`
- `flavor_tags`
- `scene_tags`
- `diet_tags`
- `feature_tags`
- `budget_level`
- `cook_time_minutes`
- `difficulty`
- `ingredients`
- `is_spicy`
- `is_vegetarian`
- `calorie_level`
- `description`

其中：

- `flavor_tags` 用于描述口味，例如鲜香、清淡、奶香
- `scene_tags` 用于描述使用场景，例如一个人吃、下午茶、朋友聚餐
- `feature_tags` 用于描述强特征，例如正餐、饮品、甜品、快手、治愈、仪式感

## 推荐逻辑概览

项目当前采用的是“规则解析 + 标签匹配 + 分数排序 + 轻随机化”的方式。

### 第一步：解析输入

用户输入一句自然语言后，系统会识别出：

- 想吃什么类型
- 偏什么口味
- 有没有预算和时间限制
- 是否表达了心情
- 是否表达了否定条件

### 第二步：构造查询

系统把输入结果和用户长期偏好合并，形成一份结构化查询：

- 偏好口味
- 场景
- 时间限制
- 预算限制
- 菜品大类
- 心情标签
- 避免类型

### 第三步：筛选菜谱池

先按硬条件过滤：

- 时间
- 预算
- 素食偏好
- 不喜欢的食材
- 正餐 / 甜品 / 饮品等大类

### 第四步：打分排序

再综合这些因素加权：

- 口味重合度
- 场景匹配度
- diet 目标匹配度
- 心情标签匹配度
- 类型匹配度
- 用户历史行为

### 第五步：加入轻随机性

在高分候选池中做有限随机挑选，减少每次都完全一样的问题。

## 当前版本的边界

目前这个项目更接近“高完成度原型”，还不是正式商用系统。

当前版本主要特点：

- 依赖本地规则解析，不是完整大模型理解
- 使用本地 CSV 菜谱库，不是在线动态内容源
- 使用本地 SQLite，不适合直接承载大规模线上用户
- 推荐逻辑以标签匹配和规则打分为主，暂未引入机器学习训练流程

## 后续可以继续扩展

- 接入大模型 API，提升自然语言理解能力
- 把规则解析升级为“标签抽取 + 意图分类”
- 接入线上数据库，如 PostgreSQL / Supabase
- 增加菜谱详情页、制作步骤页、图片资源
- 增加早餐 / 午餐 / 下午茶 / 夜宵专门模式
- 增加每周菜单规划与购物清单
- 加入真正的用户反馈闭环，例如“不想再看到这类”
- 把收藏、跳过、停留时间用于更细的个性化排序

## 一句话总结

TastePilot 想解决的不是“菜谱不够多”，而是“用户明明饿了，却很难快速决定现在到底该吃什么”。

它尝试用更自然的输入方式、更轻的标签辅助和更贴近情绪与场景的推荐逻辑，做一个会记住你口味的个人菜谱顾问。
